Follow the shared conversation and presentation protocol included below throughout this skill. Collect only the next missing decision; do not turn the initial request into a bulk questionnaire.

After read-only impact assessment, run `python3 .specify/sdd-core version-check --agent AGENT [FEATURE_UUID ...]` before proposing edits. Include every affected Feature. Run it again before applying the approved scope. Set AGENT to the current agent kind (`codex` or `claude`).
If the gate blocks, stop the requested operation and report why. Core replacement is a user action. If asked to help synchronize versions, prepare the documented `python3 .specify/sdd-core version-sync PLAN.json` preview with known existing verification commands and concrete input paths. Present the preview and wait for explicit approval before passing its hash to `--confirm`. Check the approved scope again before continuing. Git and rollback belong to the user.

Inspect development mode and active Workspaces before edits. Sync concerns external changes in the canonical origin, not automatic integration of private work. Do not run origin reconciliation while isolated work is active or treat a candidate as the origin. Core permits explicitly approved source reconciliation only after active isolated work closes. Preserve the selected mode; never use a private development integration as approval for external Sync. The returned kind=reconciliation Work Item uses its existing source Gate/complete path, without a Workspace or automatic mode change. Read-only inspection remains possible.

Start with a read-only review. Ask for a comparison base if ambiguous, then compare the actual code, contracts and official Spec Kit artifacts. Resolve candidate Features using the Source Map file paths and concrete implementation evidence, and follow changed contracts to affected dependents. Preserve the authority of approved specs. Review the affected official artifacts using the applicable official skills, without writing in this phase. Describe the proposed Baseline and authorized artifact edits, evidence, and remaining findings. Ask the user for explicit approval of this exact proposal. If the underlying files change, present an updated proposal for approval.

Do not apply edits directly from a chat-only approval. Prepare `python3 .specify/sdd-core reconcile PLAN.json` with base (kind=git/revision resolving to a commit, or kind=files/refs for explicit preserved comparison files), features, reason, nonempty findings, basis, paths (all inspected code/contracts), changes (path/content), and verification (reason/basis/gates using the existing Gate contract). The Core supports approved official specs Markdown and Baseline project/architecture/decisions/source-map edits. Use existing Feature registration/retirement commands for lifecycle changes. Do not rewrite app code or history through reconcile.

Show the preview's exact base, changes, input snapshot and verification to the user. Only after explicit approval pass `--confirm APPROVAL_HASH` to the same command. The Core rechecks current input and plan hashes, creates a reconciliation Work Item, applies approved edits and records its Gate set. Changed inputs or proposals require a fresh approval. A structural apply failure records failed, reports partial effects and requires user restoration and a new attempt. Never automatically roll back.

Use the returned Work Item ID for real `gate-run` reviews/tests or an approved `gate-refresh`; complete with actual_features, findings and evidence only after all mandatory Gates pass. A repairable validation failure stays in_progress. Preserve existing code and unrelated user changes. Re-run applicable Spec Kit reviews, existing project checks and `python3 .specify/sdd-core validate`. Surface unaddressed critical UNKNOWN and CONFLICT, and preserve the user's existing changes on failure. Report the exact approved scope applied and any failing checks. Never commit in this skill.


If reconciliation retires or restructures confirmed Features, preserve their UUID and old Work Item references. Prepare `python3 .specify/sdd-core feature-retire UUID PLAN.json` with reason, evidence file ref, successors and explicit dependency_updates for active consumers. Present the preview and wait for approval before `--confirm APPROVAL_HASH`. It archives the official directory, updates links and active source references, and preserves retired source mappings and completed history. Retired mappings are excluded from current impact and quality scope. On failure stop and let the user restore with Git; do not auto rollback. Reassess affected Discovery/Gate evidence after graph changes.

## Reconciliation continuation

A short agreement to a clearly presented, pending Sync proposal authorizes only that exact scope, not unspecified later edits. Still present the concrete Core preview and obtain the required approval before applying; changed inputs require a fresh proposal. After verification, report what was reconciled and propose returning to the interrupted task only after checking its current eligibility. Never silently restart a failed Work Item or append a Git operation to the handoff.
