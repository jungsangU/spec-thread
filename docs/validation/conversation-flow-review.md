# 대화형 질문·단계 연결 검증

2026-11-23 · 설계 1.0 · Core 0.4.0 배포 후보. [대화 UX 원본](../design/conversation-flow.md)의 구현·배포와 기존 Gate 보존을 확인한다.

## 반영 범위

- sdd-init은 기존 자료·이전 답을 읽고 현재 필요한 질문 하나씩 받는다. 전체 프로젝트·기능·제약을 한꺼번에 요구하지 않는다. 사용자가 이미 제공한 상세 설명은 재사용한다.
- Greenfield의 공식 초기 명세 → 업무 흐름 분석 → 잠정 Feature 상세화 → Gate 순서를 유지한다. Brownfield는 현행 조사부터 진행하며 새 기능을 추정해 추가하지 않는다.
- init → 구체적 기능 개발, 개발 완료 → 다음 작업, Sync 이후 원래 작업의 재검사에 같은 단계 제안 규칙을 적용한다. 짧은 동의는 구체적인 현재 제안 하나에만 연결한다.
- 현재 단계·핵심 결과·다음 선택 순서로 짧게 보여준다. 지원하는 경우에만 질문 UI·Markdown을 사용하고 전역 테마·설정은 변경하지 않는다.

## 증거의 한계

지침이 설치 파일에 포함되고 기존 Gate·저장 계약이 유지되는 것은 자동 검증한다. 실제 AI가 질문 하나만 하는지, 짧은 동의 뒤 정확한 Skill로 이어가는지, 화면이 얼마나 읽기 좋은지는 **실제 에이전트 대화 PoC가 필요하다**. 자동 테스트 결과로 모델의 매 응답이나 화면의 동일함을 보장하지 않는다.

향후 실사용에서는 (1) 빈 설명의 첫 질문, (2) 이미 상세한 설명의 재질문 생략, (3) Brownfield 자료 우선 조사, (4) READY/partial의 조건부 다음 제안, (5) BLOCKED·핵심 UNKNOWN에서 진행 금지, (6) 구체적 제안에 동의/보류/모호한 “계속”, (7) 중단 후 현재 산출물 재확인, (8) 기존 승인 범위 내 잦은 확인 생략과 필수 승인 보존을 각각 확인한다. 실제 결과와 실패 사례를 근거로 지침을 보완한다.

## 실행 결과

- 전체 제품 테스트 **73개 통과**: 기존 71개와 공통 지침의 양쪽 설치·내용 무결성 테스트 2개.
- Codex·Claude Code에 각각 설치한 총 **6개 SKILL.md**의 구조 검증 통과.
- 문서 JSON 계약 예시 13개, wheel 빌드와 실제 이전 Core 0.3.0에서의 승인 업그레이드·기존 Baseline/앱 보존 확인 통과.
- Markdown 구조·링크·설계 버전 검사와 가이드 HTML 생성 일치 확인. 실제 에이전트 응답을 자동 테스트한 결과는 아니며 위 대화 PoC 항목은 남아 있다.
