# 08 명시적 Git 통합

개발 완료와 커밋을 분리하면 Worktree별로 개발하고 검증한 뒤 필요한 요청만 함께 게시할 수 있다. 사용자는 전체 작업이 안전하게 중단·완료된 상태인지 확인하고 대상 브랜치, 선택 Worktree와 완료 ID, 포함할 파일을 지정한다.

1. `sdd-core preview PLAN.json`은 대상 기준의 임시 detached Worktree를 만든다. 소스별 공통 조상을 바탕으로 별도 인덱스에서 선택 경로의 현재 내용을 캡처한다. 스테이징에만 있는 중간 내용은 별도 입력으로 취급하지 않는다.
2. 코드, 공식 문서와 Markdown Baseline은 Git 3-way를 사용한다. 세 구조화 YAML 파일은 Feature/Work Item ID를 기준으로 비교하며 설계상 의존 목록은 Feature ID와 의존 유형으로, 파일 참조는 프로젝트 상대 경로로 병합한다. 상충하는 수정은 실패한다.
3. 선택한 Work Item이 소스 및 통합 결과에서 `completed`인지 확인하고 선택하지 않은 Work Item 기록의 변경을 거부한다. Baseline 구조를 검증하고 기준 ID, 후보 트리 ID, diff를 반환한다. 선택하지 않은 작업에 대한 의미상 의존은 diff 검토와 프로젝트 검증으로 확인한다.
4. 검토한 `reviewed_base`와 `reviewed_tree`를 사용해 `commit`을 명시적으로 요청한다. 동일한 후보 조건에서 영향 판정을 확인하고 계획의 최종 검증 명령을 실행한다. 검사 후 추적 파일, 인덱스 및 무시되지 않는 신규 파일의 변경 여부를 확인한다.
5. 검토와 검증을 통과한 트리로 단일 커밋을 만든다. 기대했던 이전 브랜치 ID에서만 반영한다. 충돌, 실패, 기준 변경 시 대상 브랜치를 갱신하지 않는다. 임시 Worktree를 정리하고 원본 Worktree를 보존한다. 수정은 사용자가 선택한 원본에서 하고 새 통합 요청에서 다시 검증한다.

Discovery Gate와 Baseline 검증을 통한 초기 분석 완료는 Git 반영과 별도다. 잠정 Feature는 확정 Feature 데이터의 통합 대상에 넣지 않는다.

현재 CLI는 기존 커밋과 같은 저장소의 Worktree를 요구한다. 대상은 어느 Worktree에도 체크아웃되지 않은 로컬 브랜치다. 최초 Baseline 커밋, 체크아웃 브랜치 안전 반영, Git hook·CI 정책 연동은 별도 과제다. 다중 Worktree 통합과 실패 시 브랜치 보존은 별도 임시 저장소에서 확인했다.
