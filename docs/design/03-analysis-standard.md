# 03 Analysis Standard

**다음 논의 · 제안 · D-001, D-002, D-004 · O-001, O-002**

| 단계 | Greenfield | Brownfield |
| --- | --- | --- |
| 입력 고정 | 요구사항 원문과 도메인 제약 | Git revision과 소스·설정·문서·테스트 범위 |
| 근거 수집 | 출처와 요구사항의 모호성 기록 | 관찰 위치와 코드·문서 사이의 충돌 기록 |
| Claim 생성 | 명시 요구사항과 해석·추가 제안을 구분 | 관찰 사실과 추론한 업무 의도를 구분 |
| 출력 | Artifact, Claim, Evidence, Source Symbol과 초기 상태 | 동일 출력 계약 |

~~~mermaid
flowchart LR
  G["요구사항 분석"] --> N["Claim과 근거 정규화"]
  B["고정 revision 분석"] --> N
  N --> V{"공통 계약 검증"}
  V -->|충족| A["Artifact 후보"]
  V -->|누락 또는 모호함| Q["질문 및 미확인 범위"]
~~~

Harness가 동일 입력과 검증 규칙을 제공하고, Claude Code와 Codex가 핵심 Claim과 근거 연결을 일관되게 생성하는지 대표 입력으로 비교하는 안을 검토한다. 표현 차이의 허용 범위는 설계에서 정한다.

1. 첫 지원 Artifact 유형, 분석 깊이와 필수 근거는 무엇인가?
2. Claim 분해, 중복 판정 및 Symbol 식별을 어떻게 표준화하는가?
3. 근거 부족과 출처 충돌을 어떤 상태로 인계하는가?
4. 두 에이전트의 결과를 어떤 필수 항목과 허용 편차로 비교하는가?

다음 산출물은 분석 입력·출력 계약 초안, 각 경로의 예제, 에이전트 간 결과 비교 기준이다.
