# SpecThread Monitor

설계 2.0 · 사용자 승인 2026-11-23. 선택 설치 모듈은 지정한 프로젝트를 읽어 화면을 제공한다. [사전 검토와 사용자 제공 시각 레퍼런스](../validation/monitor-design-review.md)

## 요구사항과 경계

- Project Overview와 SDD Pipeline은 Worktree, 분석, 공식 태스크, 설치 버전·Skill·runner 해시 대조, 저장 품질 제한의 출처를 표시한다.
- Feature·Work Item Explorer는 기존 UUID와 의존성, 선언·실제 범위 및 과거 작업 참조를 유지한다. 저장 상태의 의미는 [개발 생명주기](04-artifact-lifecycle.md)를 따른다.
- Artifact Explorer는 Spec Kit와 Baseline의 경로, 존재 여부, 수정 시각, 관측된 변경과 연결 Gate 결과를 표시한다. Gate Monitor는 실제 필수 여부, 적용 단계, 최근 실행과 증거를 표시한다. 열린 작업은 [Core 검증](06-verification.md)의 증거 유효성을 재사용하고 종료 기록은 당시 결과로 표시한다.
- Next Actions는 저장 상태에서 확인한 검토 항목과 수신한 권한·입력 요청을 제시한다. 현재 승인 대기를 확인할 근거가 없으면 화면에 미확인으로 표시한다.
- Session Monitor는 사용자가 연결한 에이전트 스트림의 세션과 파일 이벤트를 시간순 소스 순서로 보여 준다. 작업 트리 diff의 범위는 Git이고 세션에 귀속할 수 있는 경로는 에이전트 이벤트에 명시된 경로다.
- Focus와 Living은 동일한 데이터를 제공한다. Living의 야간 픽셀 사무실은 새 관측 이벤트에서만 짧게 움직인다. 키보드 탐색, 텍스트 상태, 시스템의 축소 모션을 지원한다.

## 대시보드 지표

상단에는 프로젝트에 등록된 전체 활성 Feature의 공식 태스크 체크 비율, 전체 Work Item의 완료 비율, 전체 필수 Gate의 PASS 기록 비율을 표시한다. 상세 목록의 100개 한도와 세션 이벤트·종료 여부는 이 집계의 분모를 줄이지 않는다. 폐기 Feature는 활성 태스크 집계에서 제외하고 종료 Work Item은 작업 집계에 유지한다. Gate는 열린 작업의 현재 유효 PASS와 종료 작업의 당시 PASS 이력을 나누어 표시한다. 당시 PASS를 현재 증거 재검증으로 해석하지 않는다. Gate 집합이 없는 열린 작업과 현재 유효성 미확인 개수를 함께 표시한다. 태스크를 읽지 못하거나 읽기 한도에 도달하면 미확인 Feature 수와 “확인분” 비율을 표시한다. Baseline이 없거나 유효하지 않으면 세션 이벤트로 프로젝트 진척률을 추정하지 않는다.

테스트 통과율은 현재 프로젝트의 `test-results/junit.xml`에서 읽은 최근 보고서의 통과 케이스를 실행 케이스로 나눈 값이다. 실패와 오류는 실행 분모에 포함하고 건너뛴 케이스는 별도로 표시한다. 보고서 시각은 파일 수정 시각이다. 테스트 재실행은 사용자 또는 기존 검사 흐름이 수행한다.

대시보드는 공식 태스크·프로젝트 작업 완료·필수 Gate 진행 바, 최근 테스트 도넛, 전체 Work Item 상태 분포와 세션별 최근 이벤트·변경 파일 수를 표시한다. 작업 관측 세션 수는 최근에 수신한 이벤트 기준이다. Living 사무실은 로컬 패키지의 복층 야간 픽셀아트 배경에 최대 여덟 세션 캐릭터를 두 작업 구역으로 나눠 배치한다. 사람, 로봇, 옷을 입고 두 발로 서는 호랑이·사자·고양이·여우가 같은 크기의 세션 캐릭터로 사선으로 배치된 작업석에서 모니터를 향해 작업한다. 책상, 모니터, 의자와 캐릭터는 같은 원근의 작업석 그림으로 함께 배치한다. 말풍선은 얼굴 위에 아래쪽 끝을 고정하고, 긴 제목과 상태는 말줄임표로 표시한다. 전체 문구는 세션 화면에서 확인할 수 있다. 켜진 Reader와 CEO는 앞쪽 소파에 기대앉으며, 각각 청록색과 금색 머리띠로 표시한다. 사용자 확인에는 노란 느낌표를 표시하고, 동일한 연결 Gate의 PASS를 확인하면 같은 자리에서 초록 체크를 짧게 표시한다. 성공 턴과 Work Item 완료에도 체크를 표시한다. 요청의 소실이나 다음 이벤트만으로 승인 결과를 해석하지 않는다. 축소 모션에서는 움직임을 끈다. 넓은 화면에서는 오른쪽에 세션 활동을 표시하고 좁은 화면에서는 세로로 배치한다. 좁은 화면에서는 좌우로 이동할 수 있다. 사무실에서는 한 번의 관측에서 여러 세션 활동이 바뀌면 각각 반응한다. 공식 Core Gate 명령에서 Work Item UUID를 관측하고 현재 필수 Gate의 차단 근거를 확인할 수 있으면, 연결된 세션 캐릭터의 배지가 짧게 반응하고 오른쪽 세션 Gate 목록에 표시된다. 현재 단계 밖의 미실행 Gate와 세션 연결이 확인되지 않은 작업은 이 모션의 근거로 쓰지 않는다.


사용자 확인 표시는 Core Gate UUID 연결에만 한정하지 않는다. 권한 요청, 질문·계획 승인 도구 호출, Claude의 permission_prompt·idle_prompt·elicitation_dialog 알림, 턴 종료·실패·중단을 수신한 세션에도 `!`와 텍스트를 표시한다. 턴 종료만으로 실제 승인 대기를 단정하지 않으며 “사용자 응답·결과 확인”으로 구분한다. 다음 프롬프트·도구 완료·세션 종료를 수신하면 이 표시를 해제하고 현재 Core Gate 차단 근거는 별도로 다시 계산한다. 사용자 확인 신호는 활동 유효 시간이 지나도 다음 이벤트 또는 관측 이력 보존 한도까지 유지한다. 이벤트가 전달되지 않은 대기는 추정하지 않는다.

좌측 메뉴는 세션·Feature·Work Item과 Gate·산출물·Git·Pipeline의 상세 화면으로 이동한다. 산출물 탐색에서 경로를 검색하고 선택하면 발견된 프로젝트 내부 일반 텍스트 파일의 처음 96 KiB를 미리 본다. 원문은 텍스트로 표시한다.

## 세션과 작업의 시각적 연결

세션 키는 에이전트 종류와 원래 session_id의 조합이다. 캐릭터 외형은 이 키에서 결정한다. 화면의 주 표시는 번호가 아니라 작업 주제명이다. 사용자가 지정한 주제명, 연결된 Feature 이름, 확인된 Gate·파일 작업, 작업 폴더 순서로 표시하고 근거가 없으면 “작업 주제 미확인”으로 표시한다. 색상은 키별로 화면 연결 동안 유지하며 새 세션이 추가돼도 기존 색을 바꾸지 않는다. 열 가지 팔레트를 먼저 중복 없이 배정하고 초과 세션은 색상과 식별자를 함께 구별한다. 자리나 목록 순서가 바뀌어도 같은 연결을 유지한다. 원래 세션 ID와 Work Item UUID는 상세를 펼쳤을 때만 표시한다. 색상만으로 구별하지 않도록 주제명과 활동 텍스트를 함께 표시한다. “주제 이름 설정”으로 최대 80자의 표시 이름을 지정·비울 수 있으며 현재 브라우저의 프로젝트·세션별 표시 설정으로 보관한다. 이는 Core의 상태나 에이전트 원본 세션 이름을 변경하지 않는다. 캐릭터는 다양한 머리·피부 표현의 사람, 로봇, 고양이, 여우, 식물, 외계인 등 여덟 외형이며 실제 사용자의 성별·정체성을 추정하지 않는다.

- 캐릭터 모니터·말풍선, 세션 카드, 연결된 Work Item·Gate·다음 행동은 같은 색과 작업 주제명을 사용한다. 한 작업에 여러 세션의 연결 근거가 있으면 각 세션 표식을 보여 주며 단일 소유자를 임의 지정하지 않는다.
- 말풍선과 세션 상세는 프로젝트 상대 작업 폴더, 최근 연결 Feature 이름·Work Item, 관측한 활동 종류·파일 경로·검증 Gate 이름을 보여 준다. 말풍선은 최대 다섯 자리이며 전체 세션은 세션 메뉴에서 조회한다. 종료 세션은 캐릭터 자리에서 빠지지만 보존 범위 내 상세 이력과 프로젝트 집계는 유지한다.
- 공식 Core의 stage-check·gates·gate-run·gate-refresh·transition·complete·status에서 명시한 Work Item UUID만 연결한다. Feature는 해당 Work Item의 실제 범위, 없으면 선언 범위에서 이름을 찾는다. 테스트·빌드·읽기·수정은 지원 도구와 알려진 명령의 종류로만 분류한다. 시작 신호가 있으면 “진행 관측”, 완료·과거 신호면 “최근 관측”으로 구분하며 명령 결과를 추정해 PASS로 만들지 않는다.
- 프롬프트·도구 출력·명령 본문은 저장하지 않는다. 허용한 활동 종류·상대 폴더와 파일·Gate 식별자·Work Item 참조만 정규화해 보존한다. 연결 신호가 없거나 상세 목록 밖이라 이름을 확인할 수 없으면 미확인 또는 UUID를 표시한다. 파일 동시 변경이나 대화 내용으로 세션의 업무를 추측하지 않는다.
- 세션 메뉴는 단순 permission_requested 이벤트를 기본으로 숨긴다. “권한 확인 이벤트도 보기”로 다시 볼 수 있다. 이는 표시 필터이며 사용자 확인 느낌표, 현재 관측 상태, 원본 이벤트 보존이나 Gate 판정에는 영향을 주지 않는다.

## 상세 메뉴의 탐색과 근거 확인

상세 메뉴는 전체 레코드의 필드를 한 표에 펼치지 않는다. 검색·상태 필터로 대상을 고르고 선택 항목의 정보를 별도 패널에서 확인한다. 주제명과 상태가 먼저 보이며 UUID·원본 경로는 필요한 상세에서 확인한다. 모바일에서는 선택 영역 위·상세 아래로 배치한다. 자동 스냅샷 갱신 시 검색·필터·선택·펼친 식별 정보와 읽는 위치를 유지하며, 선택 대상이 없어지면 현재 필터의 첫 항목 또는 빈 상태로 전환한다.

| 메뉴 | 탐색 단위 | 선택 항목의 상세 |
| --- | --- | --- |
| 세션 | 작업 주제·관측 상태·폴더·변경 파일 수 | 관측 활동, 연결 Feature/Work Item/Gate, 최신순 이벤트 타임라인, 표시 이름 설정, 접힌 원본 식별 정보. 권한 이벤트 기본 숨김을 유지한다. |
| Feature | 활성·폐기 상태와 태스크 진행 카드 | Discovery 기록, 태스크 비율, 순방향·역방향 의존 관계, 관련 Work Item과 공식 spec/plan/tasks 원문 이동. 관계는 현재 표시 범위에서 확인한 것임을 유지한다. |
| Work Item·Gate | Feature 또는 연결 세션 주제·저장 상태·Gate 요약 | 선언·실제 영향 범위, 연결 세션, Gate별 목적·방식·필수 여부·적용 단계·실행 횟수·현재/당시 결과·증거 참조, 관련 이전 작업. 원문 명령이나 자동 실행을 추가하지 않는다. |
| 산출물 | 경로 검색과 명세·계획·태스크·Baseline·변경 파일 종류 | 선택 파일의 원문, 경로, 현재 변경 및 Gate 상태. 기존 미리보기 경로·읽기 한도를 유지한다. |
| Git 변경 | 경로와 작업 트리·스테이징·새 파일·충돌 필터 | 선택 파일의 작업 트리/스테이징 diff, 추가·삭제·구간 색 구분과 조회 시각. 선택·탭 변경·명시적 새로고침 때만 읽는다. 늦게 끝난 이전 파일의 응답은 새 선택에 적용하지 않는다. 새 파일·충돌은 별도 안내하고 임의 파일 읽기 API를 추가하지 않는다. |
| Pipeline | 분석·명세/태스크·작업·검증·설치의 단계별 탐색 | 단계별 저장 수치와 원본 화면 이동, 현재 검증과 종료 이력 구분, 품질 제한, 연결된 다음 검토 항목. 다음 항목은 처음 네 개를 보이고 펼칠 수 있다. 여러 Feature의 병행 진행을 단일 실행 단계로 추정하지 않는다. |

화면 사이의 연결은 사용자의 선택에 따라 해당 Feature·Work Item·세션·산출물로 이동한다. 목록 한도 밖의 참조는 이름을 추정하지 않고 조회 범위의 제한을 알린다. 화면 모듈은 동일 출처의 로컬 정적 자산이며 기존 인증·읽기 전용 경계와 소스 권위를 유지한다.

### 관리자 좌석과 에이전트 실행 권한

Reader와 CEO 버튼으로 앞쪽 소파에 앉은 머리띠 캐릭터를 각각 표시한다. Reader는 활성화한 프로젝트의 지원 조회 명령에 한해 해당 에이전트 PermissionRequest에 allow를 반환한다. 열린 브라우저에서 활성화가 갱신되며 마지막 갱신 뒤 최대 10초 안에 해제된다. CEO를 사용자 화면에서 켜면 같은 프로젝트 루트에서 Monitor Hook으로 들어오는 네이티브 PermissionRequest에 allow를 반환한다. 브라우저의 갱신이 멈추면 최대 10초 뒤 만료된다. 에이전트의 자체 차단·검증과 SpecThread Core의 별도 승인 계약이 적용된다. 현재 Gate·권한 확인 상태는 원래 출처의 결과를 표시한다. SpecThread는 같은 프로젝트에서 CEO가 활성 상태인 동안 `verification-policy`, `profile`, `gates`, `gate-refresh`의 구체적 승인에 `--ceo-confirm HASH`를 제공한다. 현재 미리보기와 필수 검사 규칙을 그대로 검증한다. Reader는 Core 위임에 참여하지 않는다. 위임은 프로젝트 기준으로 적용하며 개별 에이전트 세션마다 권한을 따로 저장하지 않는다.

## 실행 구조

브라우저 → 로컬 Monitor → Core 읽기 로직·공식 산출물·읽기 전용 Git·프로젝트 Hook 기록·사용자가 지정한 이벤트 파일. Core와 Skill은 Monitor를 호출하지 않는다. 통합 설치 도구는 사용자가 선택한 경우 Monitor 패키지를 추가한다. 실행과 중지는 사용자가 제어한다. 새 에이전트 세션과 함께 연 Monitor도 에이전트 종료 후 서버와 프로젝트 화면을 유지한다. 사용자가 Monitor 터미널에서 Ctrl+C로 종료하면 서버와 임시 이벤트 파일을 정리한다. 세션 종료는 Baseline·태스크·검증 보고서를 삭제하거나 초기화하지 않는다. 브라우저가 보이는 동안 3초 간격으로 읽기 스냅샷을 요청한다. 파일 감시 서비스, 세션 조정, 자동 Git 조작, Core의 승인·검사 명령 실행, 별도 LLM 호출은 구성에 없다. [Git·세션 운영](08-git-integration.md), [소스 권위](02-source-of-truth.md)

Monitor 배포는 Core와 별도다. 0.1.0은 Core 0.5.0을 사용한다. Baseline 스키마 1을 읽고 미지원·누락·불완전 데이터는 Git과 공식 파일 관측으로 내려간다. 사용자가 설치나 마이그레이션을 선택하는 경우 [기존 버전 동기화](version-sync.md)를 사용한다.

설치 기록 대조는 대상 runner를 실행하지 않는다. 개발 진입 판단과 실제 버전 동기화의 필수·품질 Gate는 Core가 담당한다.

## 입력과 관측 한도

- 제품 루트에서 `python3 specthread install`로 앱 폴더, 에이전트, Monitor 설치 여부를 선택한다. 자동화와 기존 프로젝트에 Monitor만 추가하는 명령은 `python3 specthread install --monitor --project PROJECT`다. Core 설치 기록은 기존 설치 흐름이 소유한다.
- 설치한 프로젝트에서 macOS·Linux는 `./monitor`, Windows PowerShell은 `.\monitor.cmd`를 실행한다. 기본 명령은 브라우저와 대시보드를 열고, `--session`을 명시하면 터미널 세션도 함께 시작한다.
- 프로젝트 Hook은 Codex의 `.codex/hooks.json` 또는 Claude Code의 `.claude/settings.local.json`에 설치하고 기존 사용자 Hook을 보존한다. 프로젝트에서 따로 시작한 세션도 Hook이 로드되고 신뢰된 뒤 수신한 이벤트부터 함께 표시한다. 하위 디렉터리를 포함하며 인접 프로젝트의 작업은 제외한다. 기존 세션은 Hook 설정이 다시 로드되어야 할 수 있다.
- Windows Hook은 경로·인자를 PowerShell EncodedCommand 내부에서 개별 인용하고 stdin을 UTF-8로 전달한다. Claude에는 구버전 호환을 위해 `command` 단일 문자열을 사용하고 Codex에는 `commandWindows`를 사용한다. 최신 Claude의 exec-form `args` 지원 여부와 관계없이 동일하게 동작하도록 한다. 설치·업데이트는 기존 사용자 Hook을 보존하며 관리 Hook만 교체한다. 기존 Monitor 설치는 `update`에서 함께 갱신한다.
- 프로젝트 경로별 사용자 캐시에 세션 식별자·이벤트 종류·관측 시각·프로젝트 상대 폴더·변경 경로와 위의 허용된 작업 연결 메타데이터만 저장한다. 대시보드를 닫아도 Hook은 기록을 계속한다. 최근 256개·7일 이내 기록만 읽고 다음 이벤트 저장 시 오래된 파일을 정리한다. 프롬프트와 명령·응답 본문은 저장하지 않는다.
- Hook 실행 시간 한도는 기본 5초이고 설치 또는 추가 설치 시 `--hook-timeout SECONDS`로 조정한다. 최근 활동의 유효 시간은 기본 15분이며 실행 시 `--session-idle-seconds SECONDS`로 조정한다. 두 값은 세션을 종료시키지 않는다. 세션별 작업 관측은 최근 프롬프트 제출·도구 완료·파일 변경 신호에 근거하고, 저장된 Work Item은 별도로 표시한다.
- Codex의 [공식 exec JSONL](https://learn.chatgpt.com/docs/non-interactive-mode)은 실행당 한 파일에 사용자가 기록하여 `--codex-events FILE`로 선택한다. [Codex 공식 Hooks](https://learn.chatgpt.com/docs/hooks)의 사용자 설정 전달자도 지원한다. Codex Hooks의 패치 본문 대신 exec의 명시적 file_change 경로로 파일을 연결한다.
- Claude Code의 [공식 Hooks](https://code.claude.com/docs/en/hooks)에서 사용자가 별도로 설정한 전달자가 stdin 객체를 한 줄씩 기록하면 `--claude-events FILE`로 선택한다. `claude -p --verbose --output-format stream-json`의 세션 시작·결과 줄도 읽는다. Hooks의 파일 경로는 지정한 루트의 이벤트만 사용한다. 실시간 전달은 사용자가 선택한 인터페이스의 지원과 설정에 의존한다.
- 이벤트 수집은 최신 256 KiB를 소스별 최대 10개에서 읽고, 최근 100개를 응답에 포함한다. 프롬프트·명령 본문·도구 출력·대화의 내용은 Monitor 응답과 저장 범위에서 제외한다. 수동 지정 입력 파일은 사용자가 관리한다. 프로젝트 Hook 메타데이터는 별도 보존 범위를 따른다.
- Git 호출은 3초와 기본 256 KiB 출력 한도를 사용한다. 스냅샷은 2초 동안 메모리에 재사용하며 하나의 요청 처리 흐름에서 연산한다. Git 변경 250개, 산출물 400개, Feature·Work Item 상세는 각 100개까지 표시한다. 프로젝트 작업·Gate 합계는 크기 제한 내 Baseline의 전체 기록에서 계산한다. 활성 Feature의 태스크 파일은 합계 8 MiB까지 읽고 초과·누락은 미확인 수로 표시한다. Baseline 개별 읽기는 2 MiB, 열린 작업 Gate 증거는 작업당 8 MiB, 스냅샷당 최대 16개 작업을 확인한다. 한도 밖의 현재 Gate 유효성은 UNKNOWN이다.
- 서버는 IPv4 루프백으로만 연결하고 Host 검사, 실행마다 새로 발급하는 API 토큰, 캐시 금지와 외부 스크립트·프레임 차단을 적용한다. Git diff에는 소스 내용이 포함된다. 실행 링크는 해당 사용자에게만 제공한다.

## 위험도 기반 개발 기록 표시

Core 0.5.0의 verification.yaml을 관측 파일에 포함한다. Work Item 상세는 프로파일·분류 근거·승인 경로·필수 절차와 수행 상태를, Gate 상세는 정책 출처·재사용 출처·실제 실행 시간을 표시한다. 이전 여섯 파일 Baseline은 읽기 전용 레거시 검사로 표시하며 새 파일을 자동 생성하지 않는다. 아직 저장하지 않은 승인 미리보기를 별도 대기열로 관리하지 않는다.

상세 화면은 선택 항목에서 바로 판단할 근거를 우선 표시한다. 세션은 현재 확인 요청과 관측 파일, Feature는 남은 태스크와 차단된 Discovery 의존 관계, Work Item은 우선 검토할 필수 Gate를 보여 준다. 산출물에서 연결 Feature와 증거 참조 Work Item으로 이동할 수 있다. Git 상세는 파일의 소유권을 추정하지 않고 동일 경로를 관측한 세션을 표시한다. Pipeline은 현재 PASS로 집계되지 않은 필수 Gate 수와 상세 화면으로의 연결을 표시한다.

## 등록된 독립 작업 관측

원본 Monitor에서 같은 프로젝트 registry의 Workspace/후보만 선택 조회한다. 화면에 미반영 Scope를 표시하고 Git diff는 계속 원본을 기준으로 한다. 현재 활성 후보와 최초 사본을 구분한다. 자연 Hook의 등록 cwd를 같은 세션의 원본 이벤트로 연결하고 workspace_id를 보존한다. 임의 외부 루트·publication/history 편집 권한을 주지 않는다. 기존 Living Office·Reader·CEO 승인 범위와 Monitor 미실행 개발을 유지한다.
