결정은 사용자에게.

SpecThread는 변경 범위와 검증 결과를 보여줍니다. 일반 개발은 요청 범위에서 이어가고, 고위험·범위 확대와 Git 반영은 사용자가 결정합니다.

필요한 검증을 건너뛰지 않습니다.

필수 검증이 빠지거나 근거가 부족하면 완료를 막습니다. 수정할 수 있는 오류는 고치고 다시 확인합니다.

외부 변경은 요청할 때 살펴봅니다.

수동으로 바뀐 코드는 조사·계획·승인·적용·검증 순서로 맞춥니다. 승인된 명세를 코드에 맞춰 임의로 고치지 않습니다.

Git과 작업 환경은 직접 관리합니다.

Commit·Push·Merge·원복, 세션 운영과 Core 업데이트는 사용자 책임입니다.
