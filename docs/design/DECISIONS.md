# 설계 결정 기록

설계 1.0 · 2026-11-17 기준. 구현 상태와 검증 근거는 [통합 설계서](SpecThread-통합-상세-설계서.md)와 [미결정 백로그](OPEN-ISSUES.md)에 연결한다.

| ID | 결정 | 결정 이유 |
| --- | --- | --- |
| ST-01 | 공식 Spec Kit 독립 설치, 공식 기능 우선 및 원형 유지 | 명세·계획·태스크와 공식 도구 업데이트를 재사용한다 |
| ST-02 | Greenfield·Brownfield 공통 Feature 모델과 Baseline 6개 파일 | 입력 근거가 달라도 같은 개발 과정에서 산출물을 읽을 수 있다 |
| ST-03 | 의도·구현·실행 증거의 권위 분리 | 구현 편차가 사용자 승인 없이 제품 정책으로 굳는 일을 막는다 |
| ST-04 | 확정 Feature와 Work Item의 UUID v7, Feature와 파일 경로를 연결하는 Source Map | 참조를 이름·번호와 분리하고 병렬 변경 및 유지 비용을 줄인다 |
| ST-05 | Codex·Claude Code를 같은 정책으로 지원하고 스킬과 공통 CLI로 제공 | 의미 분석은 에이전트가 맡고 상태·구조·Git 검사 결과는 공유한다 |
| ST-06 | 핵심 UNKNOWN과 CONFLICT 차단, 비핵심 UNKNOWN은 근거 기록 | 확인 비용을 영향에 비례시키면서 중요 계약을 보호한다 |
| ST-07 | Fingerprint와 증거를 완료 이력에 보존 | 무엇을 검사했는지 구분하고 기존 이력을 유지한다 |
| ST-08 | 외부 변경은 승인형 수동 Sync | 사용자의 작업과 승인된 의도를 보호한다 |
| ST-09 · 대체됨 | 사용자 Worktree 운영, 개발과 명시적 Git 커밋 분리 | 세션 관리 복잡도를 줄이고 선택 변경을 하나의 검증된 트리로 반영한다 |
| ST-10 · 일부 대체됨 | 최초 Baseline과 Git 통합의 구체적 계약은 별도 확정 | 전체 분석 완료, 최초 Git 기준 성립, 일반 Work Item 완료를 구분해야 한다 |
| ST-11 | 공식 명세 생성·명확화를 재사용하는 Greenfield/Brownfield Discovery와 READY / CONDITIONAL / BLOCKED Gate | 업무 흐름과 현행 근거를 검토하고 경계와 요구사항을 검증한 기능만 확정한다 |
| ST-12 | 로컬 Core·Project·Skill 버전 정확히 일치. 사용자 교체와 승인 기반 메타데이터 동기화 | 배포본과 사용자가 선택한 환경을 기준으로 데이터 무결성을 지키고 자동 원격 조작을 제거한다 |
| ST-13 | 제품·대상 Git 분리. Git 조작과 병렬 세션 운영은 사용자 책임. Worktree 선택 | 개발 검증과 Git·세션 운영을 분리하고 필요한 경우 기존 검사를 재사용한다 |
| ST-14 | 개발자 브랜치와 PR, 작성자 자율 병합, 코드·문서 필수 CI, AI 의미 분석은 경고 | 실행 가능한 검사를 기준으로 병합하며 의미 검토 결과는 판단 근거로 쓴다 |
| ST-15 | 저장소 기반 AI 진입점, 독립적인 Major.Minor 설계 버전과 설계 전용 Release | 새 세션이 대화 없이 재구성하고 사용자 선택으로만 설계 버전을 변경한다 |

## 대체 및 유지 이력

| 대상 | 상태와 근거 |
| --- | --- |
| 초기 0.1의 별도 `.sdd/` 프로토콜, Claim·Source Symbol 엔터티, R0~R3 승인 | **대체**. 공식 Spec Kit와 6개 Baseline, 파일 경로 기반 Source Map, Discovery 및 영향 판정을 사용한다. 승인 의도·구현 사실·검증 증거의 권한 구분은 유지한다. [초기 초안](https://github.com/jungsangU/spec-thread/tree/54b0994/docs/design) |
| ST-09의 선택 Worktree 통합·단일 커밋 절차 및 ST-10의 전용 초기 Git 반영 계약 | **ST-13으로 대체**. 초기 분석 완료와 Git 반영을 구분하는 원칙, 사용자 주도 작업 분배, 영향·구조·증거 검증은 유지한다. 임시 통합 트리, 기대 ref, 선택 Work Item 병합 흐름은 1.0의 운영 요건에서 제외한다. [당시 상세 명세](https://github.com/jungsangU/spec-thread/blob/ed9d3d3/docs/design/08-git-integration.md) |
| 외부 변경 상시 감시 및 자동 복구, 병렬 세션 보장과 자동 조정 | **제외**. 사용자가 요청한 외부 변경 정합화와 사용자 주도 세션 운영이 확정이다. 자동 락, FIFO, 중앙 오케스트레이터와 상태 DB는 백로그 항목으로 취급하지 않는다. |
| 초기 설계 버전 0.1 | **1.0 확정**. 첫 정식 설계 기준선으로 사용자 선택을 받았다. Core 배포 버전과 독립이다. [릴리즈 노트](../../CHANGELOG.md) |

근거는 현재 요청의 확정 정책, 접근 가능한 [SDD 산출물 관리 표준 대화](chatgpt-conversation://6af31424-1064-83ec-9c80-8aad83f5143c), 로컬 Git의 `54b0994`와 `ed9d3d3` 설계 문서다. 최신 원칙과 현행 소스가 다르면 설계 원칙을 본문에, 구현 차이를 백로그에 남긴다.
