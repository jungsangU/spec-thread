# 검증 및 미결정 백로그

| ID | 구분 | 남은 항목 | 완료 기준 |
| --- | --- | --- | --- |
| ST-O1 | 실행 검증 | Claude Code 초기화·개발 및 실제 공식 스킬 호출 | 두 환경의 동일 샘플에서 공통 계약과 검증 결과 확인 |
| ST-O2 | 실행 검증 | Brownfield, 부분 초기화 재개, 다중 Feature 변경 | 기존 명세·작업 보존, 대상 경로와 영향 범위 재검증 |
| ST-O3 | 결정 필요 | 초기 분석 완료 증표 | `not_started`·`partial`·`complete`와 완료 근거의 Baseline 저장 위치 및 `sdd-develop` 진입 판정 조건 확정 |
| ST-O4 | 구현 필요 | 외부 변경 Sync의 기준 revision 선택 및 승인 입력을 적용 시점까지 고정 | 기준 revision의 선택 계약을 구체화하고, 승인 후 입력이 달라지면 중단하고 계획 재검토 |
| ST-O5 | 결정 필요 | Baseline 여섯 파일의 필수 필드·저장 위치와 스키마 버전·마이그레이션 | 변경 Feature와 영향 Feature, `SAFE`·`UNKNOWN`·`CONFLICT` 및 근거, Work Item 검증 이력을 구분한다. 폐기·통합·분리 전 UUID를 참조하는 과거 이력의 무결성과 현재 Feature로의 연결 표현을 확정한다. 기존 의존 관계 재평가 정책은 유지한다. |
| ST-O6 | 구현 필요 | 검증 파일 목록 및 검사별 연관 정보, 선택적 재검증 | 변경·삭제·이름 변경의 영향 범위를 재구성하고 이력을 유지 |
| ST-O7 | 실행 검증 | 공식 분석·수렴 출력과 Core 게이트의 결합, 필수 검증 명령의 선언 위치 | 프로젝트별 선언 위치를 확인하고 의미 소견의 누락과 검증 범위 축소를 식별 |
| ST-O9 | 실행 검증 | 실제 데모의 외부 변경 Sync | 승인 흐름과 핵심 UNKNOWN 차단을 실제 변경으로 확인 |
| ST-O10 | 보류 | 동일 프로젝트에서 두 에이전트 혼용, 별도 검증 프레임워크 | MVP 범위 이후 재검토 |
| ST-O11 | 실행 검증 | Discovery Gate 및 분리·통합·재개 | 두 경로의 순서, 요구사항 보존, 현행 근거, 세 판정과 확정 전 UUID 미발급을 확인 |

이미 확인한 범위는 Codex Greenfield 예제, 공통 CLI, 양쪽 스킬 배치 및 데모의 공식 준비 스크립트다. 최신 종단간 검증은 ST-O1·ST-O2·ST-O11로 추적한다.

## 1.0의 추가 확인 사항

| ID | 구분 | 내용 |
| --- | --- | --- |
| ST-O14 | 운영 확인 | 제품 Git 필수 검사 지정과 사용자 태그 Push 후 설계 Release 게시를 실제 저장소에서 확인한다. |
| ST-O15 | 과거 근거 미확인 | 접근이 확인되지 않은 이전 대화·첨부의 추가 결정과 원격의 기존 설계 태그 유무는 확인하지 못했다. 후속 자료가 제공되면 현재 정책과 대조한다. |
| ST-O16 | 결정 필요 | 통합 상세 설계서 §6의 Work Item `failed` 세부 판정 및 재처리 기준을 구체화한다. 기존 상태 전이와 완료 이력 보존 정책은 유지한다. |
