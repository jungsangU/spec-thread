ST-O4의 강제 바인딩·작업 기록과 ST-O6의 선택적 실행·이관은 사용자 추가 요청으로 Core 0.4.0에 구현했다. 기존 Core·Skill·Work Item·Gate만 확장하며 별도 오케스트레이터·상태 DB는 추가하지 않았다.

## 1.1 실행 검증 보완

D01~D10은 ST-33~ST-38로 확정했고 Core 0.5.0·공통 Skill에 구현했다. 검증 정의·프로파일·필수 절차·동일 Work Item 결과 활용·선택 갱신·예외 확인 및 구버전 변환의 테스트 결과는 [1.1 검증 보고서](../validation/risk-profiles-1.1-review.md)에 기록한다. 정책을 미결정으로 되돌리지 않는다.

ST-O1·ST-O7의 실제 에이전트 검증에는 새 프로파일의 의미 분류, 공식 절차 조건 선택, 실제 승인 대화와 공식 결과 활용도 포함한다. 양쪽 설치·Core 계약 비교는 통과했지만 네이티브 모델의 전체 개발 시간·실제 토큰·사용자 대화 횟수는 측정하지 않았다. 기존 ST-O17의 Windows 네이티브 확인도 유지한다.


## 1.2 실행 검증 보완

정책 11~17은 ST-39~ST-43으로 확정했다. 공통 Skill에 대상 분석·테스트·변경분 검토·문서·사실 재사용·공식 선택 기준을 반영하고 Core 0.5.1에 기존 버전 일치·누적 업데이트만 연결한다. [2차 효율화 검증](../validation/scoped-development-review.md)에서 Core 계약 시나리오와 실제 에이전트 판단·성능 미검증을 구분한다.

ST-O1·ST-O7의 네이티브 에이전트 PoC에는 T01~T20의 의미적 범위·테스트 충분성·공식 실제 호출과 필요 최소 문서 수정 준수를 포함한다. Core fixture의 의도적 결함 검출·보존·재사용은 이 PoC를 대체하지 않는다. 현재 전체 개발·문서 분석·의미 반복 분석·실제 토큰의 전후 감소는 확인하지 않았으며 확정 정책을 미결정으로 되돌리지 않는다.

## 2.0 구현·실행 검증 경계

Decision 18~38은 ST-44~ST-64로 확정했으며 미결정으로 되돌리지 않는다. 기존 ST-O1/ST-O7의 실제 Agent·공식 연동 검증을 확장한다. [검증 보고서](../validation/parallel-development-review.md)에 Core/Monitor 회귀, 실제 종료 주입, 성능과 63개 인수 항목을 대응한다.

- Codex: 현재 같은 세션의 실제 명령 cwd/절대 편집/원본 차단/권한을 확인했지만 새 fixture의 자연 Hook 원본 연결은 미확인이다. 진입은 차단 유지, 전체 네이티브 흐름 완료로 표시하지 않는다.
- Claude: 실행 파일이 없어 실제 동일 세션 PoC는 미확인이다. 공통 Core·Claude 설치/Hook·Adapter 계약은 구현하고 대체 테스트와 실제 실행을 구분한다.
- Windows 커널 잠금·경로·프로세스 생성 정체성, 외부 DB/Redis·실제 병렬 서버는 환경별 인수가 필요하다.
- Isolated의 명시적 원본 Sync는 활성 작업 종료 후 기존 승인형 reconciliation Work로 처리한다. 모드 Fallback이나 사본 통합 승인 전용은 없다. 실제 네이티브 Sync→개발 복귀 흐름은 추가 인수 대상이다.
- 복잡한 간접 의미 충돌은 Agent의 실제 판단 검증 대상이다. Core 형식 검사·텍스트 병합 통과가 의미 안전의 증명은 아니다.

추가 인수: 각 통합 종료 지점(대기·검증·반영 중 확인된 지점 외), 실제 두 서버와 외부 DB/Redis, 네이티브 의미 충돌·간접 영향. 확인된 Core/Monitor 테스트 수만으로 전체63개 통과를 주장하지 않는다.
