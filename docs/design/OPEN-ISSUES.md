# 검증 및 미결정 백로그

| ID | 구분 | 남은 항목 | 완료 기준 |
| --- | --- | --- | --- |
| ST-O1 | 실행 검증 | Claude Code 초기화·개발 및 실제 공식 스킬 호출 | 두 환경의 동일 샘플에서 공통 계약과 검증 결과 확인 |
| ST-O2 | 실행 검증 | Brownfield, 부분 초기화 재개, 다중 Feature 변경 | 기존 명세·작업 보존, 대상 경로와 영향 범위 재검증 |
| ST-O3 | 결정 필요 | 최초 Baseline 커밋 방식, 개발 진입 조건과 완료 증표 | 자동 커밋 금지와 최초 Git 기준을 충돌 없이 연결 |
| ST-O4 | 구현 필요 | Sync 승인 입력과 비교 기준을 적용 시점까지 고정 | 승인 후 입력이 달라지면 중단하고 계획 재검토 |
| ST-O5 | 결정 필요 | 초기 분석 상태·영향·검증 필드의 필수성, 버전·마이그레이션, 폐기 Feature 기록 | 여섯 파일의 호환 가능한 스키마 계약 확정 |
| ST-O6 | 구현 필요 | 검증 파일 목록 및 검사별 연관 정보, 선택적 재검증 | 변경·삭제·이름 변경의 영향 범위를 재구성하고 이력을 유지 |
| ST-O7 | 실행 검증 | 공식 분석·수렴 출력과 Core 게이트의 결합, 검증 세트 선언 | 의미 소견의 누락과 검증 범위 축소를 식별 |
| ST-O8 | 결정 필요 | 체크아웃 브랜치, 최초 커밋, staged 전용 변경, Git hooks·CI | 원본 작업 보호와 검증 트리 동일성을 유지하는 흐름 결정 |
| ST-O9 | 실행 검증 | 실제 데모의 Sync 및 다중 Worktree 통합 | 승인 흐름, 미선택 의존 및 핵심 UNKNOWN 차단을 실제 변경으로 확인 |
| ST-O10 | 보류 | 동일 프로젝트에서 두 에이전트 혼용, 별도 검증 프레임워크 | MVP 범위 이후 재검토 |
| ST-O11 | 실행 검증 | Discovery Gate 및 분리·통합·재개 | 두 경로의 순서, 요구사항 보존, 현행 근거, 세 판정과 확정 전 UUID 미발급을 확인 |

이미 확인한 범위는 Codex Greenfield 초기화·개발 예제(최신 Discovery Gate의 종단간 검증은 ST-O11), 공통 CLI와 양쪽 스킬 배치, 별도 임시 저장소의 통합 성공·실패, 후보 바뀜 차단이다. 실제 데모의 커밋은 초기 Git 기준이 필요하므로 별도 검증으로 남겨 둔다.
