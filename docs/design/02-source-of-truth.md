# 02 Source of Truth

**확정 · D-004, D-005, D-008**

| 정보 | 권위 | 불일치 처리 |
| --- | --- | --- |
| 구현해야 할 의도와 계약 | 승인된 Spec/Claim | 코드 수정안을 제시한다. 의도 변경은 별도 Spec 승인으로 처리한다. |
| 현재 구현과 구조 | 특정 revision의 대상 Git Source | 구현에서 파생된 설명과 Symbol 참조를 코드 근거에 따라 갱신한다. |
| 실행으로 확인한 결과 | Verification Evidence | 적용 범위를 점검하고 필요 시 재검증한다. |
| 미승인 의도 후보 | 원문과 근거를 검토하는 승인자 | 후보 상태를 유지하고 판단을 요청한다. |

Claim의 권위(authority)와 발견·생성 근거(provenance)를 분리한다. API 계약은 승인된 Spec을, 실제 동작은 Git Source를 기준으로 각각 확인한다.

| 위험도 | 범위 | 승인 원칙 |
| --- | --- | --- |
| R0 | 함수·클래스 존재 등 구조적 사실 | revision과 결정적 근거가 있으면 구현 사실로 자동 확정 가능 |
| R1 | 재시도·처리 순서 등 구현 동작 | 분석이나 테스트로 확인한 범위에서 구현 사실 확정 가능 |
| R2 | 업무 규칙, 설계 정책, 공개 계약 | 권한 있는 승인자 또는 명시적으로 위임된 승인 필요 |
| R3 | 인증·인가, 금전, 개인정보, 데이터 삭제 등 고위험 정책 | 지정 책임자의 강화 승인과 추가 검증 근거 필요 |

위험도는 Claim별로 영향과 근거를 함께 평가한다. 공개 API 호환성을 깨는 변경은 구조 정보라도 위험도를 높여 판단한다. R0/R1의 자동 확정은 관찰 사실에 적용한다.

~~~mermaid
flowchart TD
  C["Claim 위험도 분류"] --> F["R0/R1 구현 사실"]
  C --> P["R2/R3 의도 또는 정책"]
  F --> E{"근거 충분?"}
  E -->|예| O["구현 사실 기록"]
  E -->|아니오| U["불확실성 기록"]
  P --> A{"승인 요건 충족?"}
  A -->|예| S["승인된 의도 기록"]
  A -->|아니오| W["승인 대기"]
~~~

**미결정 · O-003** 위험도 상향 기준, 승인 권한 위임 및 증빙 요건.
